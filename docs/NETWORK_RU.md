# Eclipse + Nfqttl 4.3: пинг под нагрузкой

Этот комплект добавляет опциональный CAKE SQM. Он ограничивает скорость на
выбранном исходящем интерфейсе и распределяет очередь между потоками/клиентами.
Цель — уменьшить задержку, когда раздача загружает канал. Это не увеличение
радиосигнала, числа диапазонов или скорости тарифа. Предел скорости намеренно
ниже пропускной способности; на меняющемся мобильном канале эффект не гарантирован.

## Патч ядра

Репозиторий: https://github.com/DenBroLiik/eclipse_kernel_xiaomi_stone
Ветка: seventeen. База: cf37445a0aa9abcce4b40174ef0a6efdc8225be7, Linux 5.4.

В этой базе уже есть net/sched/sch_cake.c. Патч
kernel/0001-stone-enable-cake-sqm.patch добавляет CONFIG_NET_SCH_CAKE=y
в arch/arm64/configs/stone_defconfig. Он не меняет алгоритм CAKE или qdisc
по умолчанию. CONFIG_NET_SCHED и NF_CONNTRACK уже включены. BBR и FQ-CoDel
также уже включены — повторно «ускорять» их конфигурацией не требуется.

В checkout ядра, до сборки:

```sh
git rev-parse HEAD
git apply --check /path/to/0001-stone-enable-cake-sqm.patch
git apply /path/to/0001-stone-enable-cake-sqm.patch
```

Собери ядро штатным процессом Eclipse/RisingOS для stone, используя обновлённый
stone_defconfig. Если собираешь через дерево Android, kernel source и defconfig
должны указывать именно на этот checkout. После генерации итогового .config
проверь CONFIG_NET_SCH_CAKE=y. При использовании старого out/.config заново
примени defconfig; иначе добавленная строка не попадёт в сборку.

В комплекте нет boot.img/AnyKernel и готовой прошивки: без полного процесса
сборки и теста устройства нельзя выдать проверенный загрузочный образ.
Полная сборка ядра здесь не выполнена. Проверены применение патча, наличие
CAKE в исходниках и Kconfig. Исторический патч включения TTL/HL не нужен на этой базе.

## Модуль

Установи nfqttl-v4.3.0-eclipse.zip через KernelSU/Magisk. Он сохраняет старые
настройки и добавляет четыре новых поля со значениями 0/пусто. Перезагрузи
устройство после установки нового ядра, затем выключи и включи точку доступа.
Без нового ядра обычный TTL/HL режим работает, а включённый CAKE сообщает ошибку.

1. Включи раздачу. В WebUI посмотри раздел «Сеть»: upstream — интернет,
   downstream — интерфейс клиентов. Имена rmnet_data2 и wlan2 ниже являются
   примерами, на твоём телефоне они могут отличаться.
2. Измерь устойчивую отдачу и загрузку на клиенте несколько раз. При одновременной
   загрузке измерь пинг к одному и тому же адресу. Начальный ориентир для предела
   CAKE — около 85–90% устойчивой скорости, затем подбери его по замерам.
3. Открой «Пинг под нагрузкой · CAKE». Введи пределы в кбит/с и реальные имена
   интерфейсов. Для 10 Мбит/с отдачи примерный начальный предел — 8500 кбит/с.
   Значение 0 выключает соответствующее направление.
4. Оставь «Отключать ускорение раздачи» включённым, сохрани настройки и проверь
   состояние CAKE в разделе «Сеть». Аппаратный IPA/BPF обход может исключать
   пакеты из программных очередей; настройки offload сами по себе не доказывают
   его отсутствие. Для live проверки смотри счётчики через tc -s qdisc show,
   если tc доступна, и dumpsys tethering.

Пример команд для известных интерфейсов и канала 10/50 Мбит/с:

```sh
su -c '/data/adb/modules/nfqttl/nfqttl configure SQM_UP_IFACE=rmnet_data2 SQM_UP_KBIT=8500 SQM_DOWN_IFACE=wlan2 SQM_DOWN_KBIT=42500 DISABLE_OFFLOAD=1'
su -c '/data/adb/modules/nfqttl/nfqttl qos'
```

Не копируй эти скорости и имена без проверки. Все команды доступны через
control.sh, если установленный исполняемый файл находится в нестандартном модуле.

Отключение CAKE:

```sh
su -c '/data/adb/modules/nfqttl/nfqttl configure SQM_UP_KBIT=0 SQM_DOWN_KBIT=0'
```

Модуль работает с CAKE напрямую через NETLINK_ROUTE; команда tc и отдельная
динамическая библиотека не требуются. Для изменения qdisc нужен CAP_NET_ADMIN;
SELinux/root manager могут запрещать операцию, что видно в диагностике.

## Область действия и ограничения

- Отдача: CAKE на физическом upstream ограничивает весь его исходящий трафик,
  включая приложения телефона. dual-srchost + NAT различает клиентов раздачи.
  Не ставь его одновременно на CLAT и нижележащий rmnet: двойное ограничение
  ухудшит работу. Модуль отвергает upstream v4-* и clat*.
- Загрузка: CAKE на downstream ограничивает передачу клиентам одного выбранного
  интерфейса раздачи (dual-dsthost + NAT). Он не ограничивает загрузку самого
  телефона и не управляет всеми downstream одновременно. Это egress shaping,
  не полноценная обработка входящего канала через IFB. Пакеты уже прошли радио;
  неконтролируемый входящий UDP может перегрузить канал до очереди CAKE.
- Очереди upstream существуют после модема/радиопланировщика; CAKE не управляет
  очередями оператора. Если реальная скорость упала ниже заданного предела,
  задержка может снова вырасти. Автоматической оценки радиоканала в этом релизе нет.
- Режим besteffort, память 4 МиБ на интерфейс, RTT 100 мс, split-GSO включён,
  фильтрация ACK отключена. DSCP не используется для повышения приоритета.
  Накладные расходы радиоканала не угаданы. При большой скорости CAKE увеличивает
  нагрузку CPU; проверь температуру и расход батареи на своём устройстве.
- Модуль применяет очереди только при активной раздаче и наличии выбранных
  интерфейсов в обнаруженной роли. Проверка раз в 30 секунд и при смене сети.
  После смены SIM/upstream обнови явно выбранный интерфейс.
- Применяются только штатные корневые qdisc с handle 0 или скрытый builtin/noop.
  Пользовательские корневые/дочерние очереди сохраняются. Установка CREATE|EXCL
  не перезаписывает конфликтующий root между проверкой и применением.
- Перед установкой сохраняется журнал владения. Остановка, пауза, смена сети
  и выключение CAKE удаляют только cake 7e10: с совпадающим ifindex и полным
  набором параметров. Удаление возвращает ядру его штатный qdisc; произвольный
  предыдущий пользовательский qdisc модуль не принимает под управление.
  При внешнем изменении параметров очередь сохраняется. Это не атомарная
  транзакция с чужими concurrent tc-командами: не меняй тот же qdisc одновременно.

TTL/HL и IPA: в просмотренном UAPI IPA нет подтверждённой операции установки
произвольного TTL/HL. Включить offload, сохранив гарантированную нормализацию,
этот патч не позволяет. Модуль продолжает использовать netfilter и управлять
отключением offload. Модем, RF, регуляторные ограничения и Wi-Fi драйвер не меняются.
